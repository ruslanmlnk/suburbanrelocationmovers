# Suburban Relocation Systems — WordPress theme

Готова класична WordPress-тема з підтримкою Gutenberg. Не потребує ACF або платного конструктора.

## Встановлення

1. У WordPress відкрийте **Appearance → Themes → Add New → Upload Theme**.
2. Завантажте ZIP-архів теми й активуйте її.
3. Перейдіть у **Appearance → Starter Content** та натисніть **Import starter content**.
4. Якщо адреси сторінок повертають 404, один раз відкрийте **Settings → Permalinks** і натисніть **Save Changes**.

Імпортер не перезаписує записи або сторінки, якщо вони вже мають такий самий slug.

## Що і де редагувати

- **Appearance → Home Sections** — уся головна сторінка редагується по секціях: Hero, форма, переваги, Services, Process, Locations, Reviews, FAQ і CTA. Верстка секцій зафіксована темою, тому стандартні стилі Gutenberg більше її не ламають.
- **Services** — додавання й редагування сервісів. Title, Excerpt, Featured Image та повна стаття редагуються стандартними блоками Gutenberg. Поля `Hero kicker` і `Short card label` — у правій панелі редактора.
- **Locations** — додавання й редагування локацій та міських SEO-сторінок. Є окремі поля для регіону, адреси, телефона та зони обслуговування. Увімкніть **Show in the home-page Locations section**, якщо локація має бути на головній.
- **Quote Requests** — усі заявки з форм. Навіть якщо поштовий сервер ще не налаштований, заявка зберігається тут.
- **Appearance → Company Details** — телефон, email, графік, основна адреса, email для заявок і ліцензійні номери.
- **Appearance → Customize → Site Identity** — заміна логотипа.
- **Appearance → Menus** — редагування головного меню. Підменю на десктопі відкриваються при наведенні; на телефоні — окремою кнопкою.

## Динамічні секції

Динамічні сітки доступні також як короткі коди:

```text
[srs_services_grid count="-1"]
[srs_locations_grid count="-1" featured="yes"]
[srs_quote_form]
```

Тому нові сервіси з’являються в сітці автоматично. Для нової локації додатково поставте прапорець показу на головній.

## Форма оцінки

Поля відповідають погодженому набору:

- Full name — optional
- Phone number — required
- Preferred move date — optional
- Email — optional
- Moving from — optional
- Moving to — optional

Після відправлення WordPress спочатку створює приватний запис у **Quote Requests**, а потім незалежно відправляє повідомлення через Resend API та заявку в Granot. CF7 і SMTP для цих форм не потрібні. Помилка зовнішнього API не видаляє збережену заявку.

### Налаштування Resend і Granot

Відкрийте **Quote Requests → Form integrations**:

1. Введіть Resend API key з правом відправки листів і email відправника на підтвердженому в Resend домені.
2. Вкажіть email для отримання заявок. До першого збереження налаштувань використовується адреса з **Company Details**; після цього адресою керує **Form integrations**.
3. Granot увімкнено за замовчуванням з погодженим `label=suburbanrelocationmovers`. Endpoint: `https://api.starvanlinesmovers.com/Granot/send`. Передаються `firstname`, `email`, `phone1`, `ozip`, `dzip`, `movedte` (YYYY-MM-DD), порожній `movesize`, сторінка джерела в `notes` та `label`.
4. Збережіть налаштування. Після налаштування перевірте контрольну заявку в Resend та безпосередньо у CRM.

Ключ зберігається лише на сервері, не показується повторно в HTML і не потрапляє в журнал. Порожнє поле ключа зберігає попереднє значення. Замість поля можна задати константу `SRS_RESEND_API_KEY` у `wp-config.php` або однойменну змінну середовища PHP. Не додавайте ключ у Git. На Docker-хостингу змінну необхідно передати контейнеру WordPress.

Журнал на сторінці інтеграцій показує статуси, час, HTTP-коди, обмежені до 4000 байтів відповіді API та історію останніх 30 подій кожної заявки. Доступ до налаштувань, журналу і ручної відправки мають лише адміністратори (`manage_options`). Список заявок має окремі колонки Resend / Granot.

«Прийнято API» для Resend означає отриманий email ID, а не доставку у скриньку. Для Granot це успішна HTTP-відповідь шлюзу без відомої ознаки помилки: остаточну появу заявки потрібно перевірити у CRM, оскільки контракт відповіді шлюзу не надано. Сирі відповіді можуть містити дані клієнта, тому журнал закритий від відвідувачів.

Невідправлені заявки можна надіслати окремо в потрібний сервіс із журналу. Автоматичних повторів у Granot немає: після тайм-ауту спочатку перевірте CRM, щоб не створити дубль. Resend використовує незмінний payload та `Idempotency-Key` для повторів протягом 24 годин. Після завершення цього вікна потрібна перевірка в сервісі й підтвердження нової спроби.

Форми перевіряють телефон, email і дату на сервері, використовують honeypot та обмеження 10 нових заявок за 10 хвилин на IP. За reverse proxy налаштуйте передачу справжнього IP на рівні сервера; неперевірені заголовки X-Forwarded-For не використовуються. Ідентичні заявки протягом 10 хвилин зберігаються один раз. З JavaScript форма надсилається без перезавантаження, оновлює nonce для кешованих сторінок і зберігає введені дані при помилках; без JavaScript працює звичайний POST. Підтвердження користувачу означає, що заявку збережено у WordPress.

Контрактні перевірки з підміненим HTTP (без реальних листів і заявок): `php tools/check-form-integrations.php` з кореня репозиторію.

Перевірка поведінки форми: `node tools/check-quote-forms.cjs`. Контракт Resend: [Send Email](https://resend.com/docs/api-reference/emails/send-email), [Idempotency Keys](https://resend.com/docs/dashboard/emails/idempotency-keys).

## Шаблони та адаптивність

- окремі архіви й сторінки Services та Locations;
- шаблон довгої статті з текстом, зображеннями, списками та формою в sidebar;
- сторінки Testimonials, Moving Tips і Contact;
- адаптивні header, hover-dropdown, форми, сітки та footer;
- власна палітра й стилі в редакторі Gutenberg;
- reusable patterns: Article section with image і Quote call to action.

## Системні вимоги

- WordPress 6.3+
- PHP 7.4+
